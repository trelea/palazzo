# Taste
- Prefers compact content bands over full-viewport (`min-h-svh`) sections — call-to-action blocks should feel like a section band, not a full-height screen. Confidence: 0.6
- Wants new UI sections to have a distinct visual treatment rather than cloning an existing pattern (e.g. not a copy of the existing appointment band), while still keeping it simple and polished. Confidence: 0.6
- When two CTAs sit side by side, they must be exactly the same width and height (e.g. a two-column grid or equal flex basis), not sized by their own content. Confidence: 0.7
- When asked to remove a feature/UI element, remove it completely — no commenting out or hiding; also clean up the now-unused imports and i18n keys it introduced. Confidence: 0.6
- Wants loading media to show a simple branded skeleton (a pulsing panel with the brand/logo mark) instead of blank space, fading out once the image paints. Confidence: 0.5
- Cares about SEO/metadata rigor — expects feature/branch changes to be reviewed against the full SEO surface (canonical + hreflang, OG/Twitter, JSON-LD, sitemap, alt text) and asks for a prioritized gap analysis of what's missing or could be improved, not just a confirmation. Confidence: 0.55
- Prefers subtle, incremental visual tweaks ("not very much, just a little bit") over bold/large changes, and expects responsive adjustments scoped to the requested breakpoint (e.g. desktop `lg:` only) with mobile left untouched. Confidence: 0.5
- Wants a booking/conversion CTA placed contextually where the reader finishes content (e.g. a "Book Now" button right after the last item of the procedures list), not only in a dedicated CTA section — and the same treatment applied consistently to every parallel section (e.g. both the Face and Body panels). Confidence: 0.55
- Wants primary/CTA buttons to span the full content width on small screens (`w-full` … `sm:w-auto`), reverting to an auto-width centered button from the `sm` breakpoint up. Confidence: 0.55
- Wants websites attributed to the agency that built them and its founder/lead developer — inject as much of it as possible: `Organization` + `Person` (with LinkedIn) JSON-LD, `author`/`creator`/`developer` meta tags, and a visible footer credit linking the agency site, the developer's LinkedIn, and contact email/phone. Confidence: 0.6
- Never hardcode user-facing strings in components — route all copy through the project's existing i18n/translation system and add keys for every supported locale. Confidence: 0.65
- Wants translations to read naturally and preserve the original tone in each language, not be literal word-for-word renderings. Confidence: 0.5
- New UI must reuse the site's existing fonts, color palette and spacing — no introducing new styling that breaks the established design. Confidence: 0.55
- Expects responsive behavior explicitly checked at ~360px, 768px and 1280px+ (no horizontal overflow, no awkward line breaks). Confidence: 0.55
- When the task premise is uncertain or a request may already be satisfied, wants the actual current state surfaced and a decision confirmed before making changes, rather than blindly implementing — and wants the investigation reported concisely (files touched, placement, choices). Confidence: 0.55
- Once a change is wanted, expects the agent to actually implement it (edit the files) rather than stop at verification/reporting — pushing back when the deliverable is only a verification summary with no code changes. Confidence: 0.55
- Prefers the simplest possible solution: place content inline within the existing element/structure (e.g. one line right under the hero lead) rather than building a separate dedicated section, band, or component — explicitly asks for "simple". Confidence: 0.6
- Dislikes loud, saturated full-width banner strips (e.g. a colored bar pinned right under the navbar) that read like a promo/announcement banner; prefers understated, elegant, editorial treatments (centered, soft background band, display-serif type) that stay subordinate to the primary content instead of competing with it. Confidence: 0.5
